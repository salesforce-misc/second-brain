# second-brain-setup

Bootstrap or update one second-brain wiki directory. Creates the directory structure,
starter files, and one managed project instruction section. Safe to run multiple times
(idempotent).

## What it does

1. Scaffolds directories if they don't exist
2. Creates starter files if they don't exist (never overwrites)
3. Updates a bounded section in `AGENTS.md` (creates or replaces)

## Instructions

### 1. Resolve the brain root

Claude Code shorthand is `/second-brain-setup [brain]`. In Codex and OpenCode,
invoke the `second-brain-setup` skill with the optional brain. Treat the current
directory, or a project path supplied by the user, as the project root. Resolve the
project root to its physical path before discovery.

Discover an existing root brain at `wiki/index.md` and named brains at
`brains/**/wiki/index.md`. Ignore a candidate when any path segment is named
`_template`.

Resolve the target as follows:

- If the user supplied `root` or `.`, use the project root.
- If the user supplied a brain, remove one optional leading `brains/`. For a
  slash-free selector, match all discovered brains with that final directory name.
  Use it only when the match is unique. If several match, list them and require a
  path such as `team/foo`, even when one match is `brains/foo`. If none match, use
  `brains/<brain>` as the new brain root.
- For a selector that contains a slash, use its exact path under `brains/`. Create a
  new brain at that path when it does not exist.
- Reject absolute brain paths and any brain path that contains `..` or `_template`.
- If the user omitted the brain and exactly one brain exists, use it automatically.
- If the user omitted the brain and several brains exist, list them and ask the user
  to choose. Stop before creating files.
- If the user omitted the brain and no brain exists, use the project root. This keeps
  the existing single-root setup behavior.

Before creating any file, resolve the selected target through every existing symlink
component. For a named brain, require the resolved target to remain under the
physical project root's literal `brains/` directory. Reject the target if a symlink
in `brains/` or below it escapes that boundary. Use the validated brain root for
every relative path in the remaining steps.

### 2. Scaffold directories

Create these directories if they don't exist:

```
raw/
raw/extras/
wiki/
wiki/concepts/
wiki/sources/
output/
```

Use `mkdir -p` for each directory. Track which ones were created vs already existed for the report.

### 3. Create starter files (only if missing)

For each file below, check if it exists first. Create only if missing. Never overwrite existing files.

#### wiki/index.md

```markdown
# Wiki Index

*No articles yet. Add source documents to `raw/` and run second-brain ingest. Claude Code shorthand is `/second-brain ingest`.*
```

#### wiki/connections.md

```markdown
# Connections

Cross-cutting themes and links between concepts.

*Updated automatically during ingest and compile passes.*
```

#### raw/links.yaml

```yaml
# Links to fetch during ingest
# - url: https://example.com/doc
#   type: help-salesforce | wiki | google-doc | web
#   found_in: <source that referenced this link>
#   page_id: "12345"  # (wiki only)
```

#### raw/pull-all.sh

```bash
#!/usr/bin/env bash
# Pull all git repos under raw/
#
# Usage: ./pull-all.sh

set -euo pipefail

cd "$(dirname "$0")"

for dir in */; do
  if [[ -d "$dir/.git" ]]; then
    echo "==> Pulling $dir"
    (cd "$dir" && git pull --ff-only)
  fi
done

echo "Done."
```

After creating this file, make it executable: `chmod +x raw/pull-all.sh`

### 4. Update bounded project instructions

Apply this step to `AGENTS.md` in the resolved brain root. The section tells each
supported runtime to use the shared skill. Do not create or change `CLAUDE.md`.

Before reading or writing the file, inspect its directory entry without following
symlinks. If the entry exists, require a regular non-symlink file. Resolve its path
and require it to remain inside the validated brain root. If it is a symlink,
directory, special file, or resolves outside the brain root, do not read or write it.
Report the unsafe path. Create a missing instruction file only at its direct path
inside the validated brain root.

If an instruction file does not exist, create it with only this section:

```markdown
<!-- GENERATED BY second-brain -->
This is a second-brain wiki project. Use the second-brain skill before acting on wiki content. Claude Code shorthand is /second-brain.
<!-- END second-brain -->
```

If the file exists, read it and look for the delimiters:
- Start: `<!-- GENERATED BY second-brain -->`
- End: `<!-- END second-brain -->`

If each delimiter occurs exactly once and in the correct order, replace only the
content between them. Keep both delimiters and all unrelated content unchanged.

If neither delimiter exists, append the section at the end of the file:

```markdown

<!-- GENERATED BY second-brain -->
This is a second-brain wiki project. Use the second-brain skill before acting on wiki content. Claude Code shorthand is /second-brain.
<!-- END second-brain -->
```

If only one delimiter exists, either delimiter occurs more than once, or the end
appears before the start, do not edit that file. Report the malformed bounded
section and ask the user to repair it. Do not replace unrelated content.

The content between delimiters must be: `This is a second-brain wiki project. Use
the second-brain skill before acting on wiki content. Claude Code shorthand is
/second-brain.`

### 5. Report results

Print a summary:

```
second-brain-setup completed:

Brain root: <path relative to project root>
Directories created: [list] or "none (all existed)"
Files created: [list] or "none (all existed)"
AGENTS.md: created / updated managed section / managed section already up to date
```

Be specific about what changed vs what was already in the correct state.

For Claude Code, require the built-in `agents-md@builtin` plugin to be enabled.
Its default `claude-md-or-agents-md` mode loads `AGENTS.md` only when the project
has no `CLAUDE.md`, `.claude/CLAUDE.md`, or `CLAUDE.local.md` from the project root
through the working directory. Configure a different mode through the user,
`--settings`, or managed settings. Project `.claude/settings.json` does not apply
plugin options.
