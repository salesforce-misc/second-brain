# Second Brain Doctor

Diagnose first. Reuse Git for file moves and `second-brain-setup` for the managed
block. Do not parse or rewrite unrelated instructions.

## Safety rules

- Treat the supplied repository, or the current repository, as the project root.
  Resolve its physical path before discovery.
- Inspect directory entries without following symlinks. Read only regular,
  non-symlink UTF-8 files whose resolved paths stay inside the physical project
  root.
- Stop changes for an unsafe file, invalid UTF-8, or malformed second-brain marker.
  Report the exact path and reason.
- Diagnose without changing files. Ask for explicit consent before each proposed
  content move or wrapper replacement. Consent to diagnose is not consent to change
  files.
- Never move or delete `.claude/CLAUDE.md` or `CLAUDE.local.md`. Report either as a
  manual blocker.
- Never move a `CLAUDE.md` that contains an active `@AGENTS.md` import into
  `AGENTS.md`. It can overwrite the canonical content that the import expects.
- Preserve both files when content is ambiguous. Do not merge instruction prose.
- Do not change Claude Code user or managed settings.

The managed block has exactly these markers, once each and in this order:

```markdown
<!-- GENERATED BY second-brain -->
<!-- END second-brain -->
```

Neither marker means the managed block is absent. Exactly one marker, a duplicate
marker, or reversed markers are malformed and block changes in that instruction
chain.

The transitional Claude Code wrapper is exactly:

```markdown
@AGENTS.md

```

An exact wrapper with a same-directory, real, non-wrapper `AGENTS.md` is a valid
`TRANSITIONAL` state. The wrapper imports the canonical file. Removing it is a
future explicit migration step, not this doctor's default.

An exact wrapper with no `AGENTS.md`, or any `AGENTS.md` that contains an active
`@AGENTS.md` self-import, is `BROKEN_TRANSITION`. This state has priority over every
other classification. Block automatic migration and require manual recovery of the
canonical content.

An active import is a line whose trimmed content is exactly `@AGENTS.md` and that is
not inside a fenced code block. A `CLAUDE.md` with an active import but no
same-directory `AGENTS.md` also blocks automatic migration.

## 1. Discover brains and instruction chains

The root brain index is `wiki/index.md`. Named brain indexes match
`brains/**/wiki/index.md`. Ignore a candidate when any path segment is `_template`.
Resolve each candidate before use. Require every brain root to stay inside the
physical project root, and every named brain to stay inside its literal `brains/`
directory. Reject a symlink escape.

In a Git repository, discover existing owned brains from tracked and non-ignored
untracked index files:

```sh
git ls-files -z -- ':(glob)wiki/index.md' ':(glob)brains/**/wiki/index.md'
git ls-files --others --exclude-standard -z -- ':(glob)wiki/index.md' ':(glob)brains/**/wiki/index.md'
```

Require the index and brain root to remain outside nested repositories. An existing
index that Git does not enumerate is not repository-owned. An ignored brain or a
brain inside a nested repository can be reported when an exact supplied path reveals
it, but it is diagnosis-only and must never be a setup or migration target. Do not
crawl the filesystem to find additional candidates.

Before proposing a new Git setup target, use Git to verify that its planned
`wiki/index.md` is not ignored. Reject the target if an existing path component is a
symlink or contains a nested `.git` entry. If no owned brain exists and the project
root passes these checks, keep it as the only new setup candidate.

```sh
git check-ignore -q --no-index -- <brain-root>/wiki/index.md
```

Exit status zero means the planned index is ignored, so do not propose setup there.

In a non-Git repository, inspect only the exact root `wiki/index.md` and exact brain
roots the user supplies. Require the user to confirm each exact brain root as
repository-owned before proposing setup or migration. A candidate without that
confirmation is diagnosis-only.

For each owned brain, inspect each directory from the project root through the brain
root. At every directory, diagnose these paths when present:

```text
AGENTS.md
CLAUDE.md
.claude/CLAUDE.md
CLAUDE.local.md
```

Keep the chain inspection explicit even when a chain file is ignored or untracked.
For descendant discovery in a Git repository, enumerate only tracked and
non-ignored untracked files with Git. Use NUL-delimited output and these exact
instruction filename pathspecs:

```sh
git ls-files -z -- ':(glob)AGENTS.md' ':(glob)**/AGENTS.md' ':(glob)CLAUDE.md' ':(glob)**/CLAUDE.md' ':(glob)CLAUDE.local.md' ':(glob)**/CLAUDE.local.md'
git ls-files --others --exclude-standard -z -- ':(glob)AGENTS.md' ':(glob)**/AGENTS.md' ':(glob)CLAUDE.md' ':(glob)**/CLAUDE.md' ':(glob)CLAUDE.local.md' ':(glob)**/CLAUDE.local.md'
```

Do not use a filesystem crawl. Git enumeration excludes ignored dependency and
build trees. Reject any enumerated path inside a nested repository, or below a
directory with its own `.git` entry. Never inspect `.git` internals. Do not follow
symlinked files or directories. Keep only paths below a discovered brain root. For
each nested plain `CLAUDE.md`, also inspect same-directory `AGENTS.md` so the
classification rules apply. If that counterpart exists but Git does not enumerate
it, report an unowned destination blocker. Do not read or change it.

In a non-Git repository, do not crawl descendants. Inspect the explicit instruction
chains and any exact additional repository-owned paths that the user supplies. Ask
the user to confirm that this is the complete owned scope. Without that confirmation,
report descendant coverage as incomplete and do not claim repository-wide readiness.

Deduplicate all explicit and enumerated paths. An explicit chain path outside the
owned scope is diagnosis-only. In a Git repository, only Git-enumerated owned paths
can appear in a content-move or wrapper-replacement plan. In a non-Git repository,
only exact paths the user supplied and confirmed as repository-owned can appear in
that plan.

For each regular UTF-8 file, report its path and any managed block as absent,
current, stale, or malformed. Current means the complete block matches the block
required by `second-brain-setup`. An ancestor or descendant `AGENTS.md` with no
managed block is neutral project instruction content. Only a brain-root `AGENTS.md`
must contain the current block.

Diagnose both `agents-md@builtin` enablement and its effective `instructionFiles`
mode. Use the current Claude Code plugin and configuration views when available. A
read-only `claude plugin list` can establish enablement, but not the effective mode.
If either value cannot be verified, report it as `unknown` and tell the user to check
`/plugin` and `/config`. Never enable the plugin or edit settings.

Claude Code is ready only when `agents-md@builtin` is enabled and the effective mode
is `claude-md-or-agents-md` or `claude-md-and-agents-md`. Treat `claude-md`,
`managed-only`, any other value, or `unknown` as not ready. Explain that
`claude-md-or-agents-md` ignores `AGENTS.md` when `CLAUDE.md`,
`.claude/CLAUDE.md`, or `CLAUDE.local.md` exists on the active project path. The
exact transitional wrapper is compatible with this mode because it imports the
canonical `AGENTS.md`.

## 2. Classify each directory

Apply these rules only to same-directory `CLAUDE.md` and `AGENTS.md`, including
nested plain `CLAUDE.md` files found in a brain subtree. A manual blocker anywhere
in an instruction chain or brain subtree prevents automatic migration for that
brain.

Evaluate the table from top to bottom. The first matching state wins.

| State | Diagnosis and proposed action |
|---|---|
| Exact wrapper with missing `AGENTS.md`, any `CLAUDE.md`-only active import, or `AGENTS.md` has an active self-import | Report `BROKEN_TRANSITION`. Preserve files and require manual recovery of canonical content. |
| `CLAUDE.md` only, with no active `@AGENTS.md` import | Offer to move the whole file to same-directory `AGENTS.md`, then create the exact wrapper at `CLAUDE.md`. Run setup only for affected brain roots with a missing or stale block. |
| `AGENTS.md` only | Preserve an ancestor file. At a brain root, report current or offer setup for a missing or stale valid block. |
| Exact wrapper plus real, non-wrapper `AGENTS.md` | Report `TRANSITIONAL`. At a brain root, offer setup only when the managed block is missing or stale. |
| Both, byte-identical | Offer to replace `CLAUDE.md` with the exact wrapper. Run setup only when the brain-root block needs it. |
| Both, `CLAUDE.md` becomes whitespace after removing one valid managed block and `AGENTS.md` is current | Offer to replace `CLAUDE.md` with the exact wrapper. |
| Both, any other content | Report a conflict and preserve both files for manual reconciliation. |
| Neither | At a brain root, offer setup. At an ancestor, no action is needed. |

Do not propose an automatic action when either file has malformed markers. A stale
but valid block is repairable only through `second-brain-setup` and only after
consent.

Print one plan that lists every file whose content will move, whose content will be
replaced by the wrapper, or that setup will repair or create. Include all manual
blockers and conflicts. If the plan has no changes, stop after the report.

## 3. Apply an approved plan

After explicit consent, re-run the full diagnosis. Stop if the state differs from
the approved plan.

For an approved move, check whether Git tracks `CLAUDE.md`:

```sh
git ls-files --error-unmatch -- CLAUDE.md
```

Run `git mv -- CLAUDE.md AGENTS.md` when tracked. Otherwise use the platform's
ordinary same-filesystem move. Use paths relative to the affected directory. Do not
overwrite an existing destination. Then create the exact transitional wrapper at
`CLAUDE.md`.

For an approved identical or managed-only case, replace `CLAUDE.md` content with the
exact wrapper. Do not delete `CLAUDE.md`. Never replace ambiguous content.

Invoke `second-brain-setup` for each brain that needs a missing, stale, or moved
managed block. The setup skill owns block creation and replacement. Do not edit the
block manually. Invoke setup only for a brain root that passed the ownership checks.

## 4. Verify

Re-run the diagnosis and require all of these results:

1. Every owned plain `CLAUDE.md` on an explicit instruction chain or in the complete
   descendant scope is the exact transitional wrapper and has a same-directory,
   real, non-wrapper `AGENTS.md`. No `.claude/CLAUDE.md` or `CLAUDE.local.md`
   remains. For a non-Git repository, require the user's scope confirmation before
   this check can pass.
2. Each brain root has one real, non-wrapper `AGENTS.md` with no active
   `@AGENTS.md` self-import and with one ordered managed marker pair.
3. Each setup target passed its Git ownership check or explicit non-Git ownership
   confirmation. Ignored and nested-repository candidates remain diagnosis-only.
4. The managed block is current.
5. A second `second-brain-setup` run proposes no file change.
6. `git diff --check` passes when the project is a Git repository.

Report changed paths, unresolved blockers, `agents-md@builtin` enablement, the
effective `instructionFiles` mode, owned-scope coverage, and the idempotence result.
Do not claim repository-wide readiness when owned-scope coverage is incomplete or an
unowned chain file remains. Do not claim Claude Code support is ready unless the
plugin is enabled and the mode is compatible.
